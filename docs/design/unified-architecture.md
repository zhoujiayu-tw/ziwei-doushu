# 統整架構：一個天空、三把尺

> 對象：`ours.zhoujiayu.app/bazi`（雙人節氣曆 v5，repo `bazi-zodiac-calendar`，已封存）裡的八字十神、紫微流年、西洋行運、配飾配色，要怎麼併進 `bz.zhoujiayu.app`。
> 標記同 concept.md：✔ 程式裡驗證過；📜 古籍或文獻；◇ 類比或推想。

## 0. 結論

三套系統的輸入完全相同：**一個時刻、一個地點**。它們共用三個天文量 —— 太陽黃經、月亮黃經、地方恆星時 —— 差別只在把這些連續量切成格子的方式。所以架構上應該只有一個「天空層」算天文，上面接三個「刻度層」各自切格，再接各自的文案庫；畫面上只有一條時間軸、一片天空，三把尺並排讀。

## 1. 舊 app 盤點

| 區塊 | 算法 | 性質 |
|---|---|---|
| 年柱、日柱 | 60 循環計數（日柱以 1949-10-01 甲子為錨） | 即時、精確 |
| 月柱 | 固定節氣日期表（±1 天） | 即時、近似 |
| 十神、今日／本月／本季文案 | `tenGod()` + 男女各一套十神文案 | 即時；文案含兩人的具體處境（創業、收入） |
| 月相 | 平均朔望月 | 即時、近似 |
| 紫微流年主題 2026–2033 | 寫死表（事先用 iztro 算） | 非即時 |
| 年度外行星行運 2026–2033 | 寫死表（事先用 Swiss Ephemeris 算） | 非即時 |
| 太陽／月亮星座、本週相位 | 低精度公式 + 本命點寫死（`NATAL`） | 即時；男命上升為假設 |
| 水星逆行 | 寫死區間 2026–2028 | 非即時 |
| 身心安頓、配飾文玩 | 依十神與日主五行查表 | 文案 |
| 目標看板、兩份檢核清單 | localStorage | 不是命理，是兩人的待辦 |

四個寫死表都會在 2028–2033 到期；兩人的本命資料與文案直接寫在原始碼裡。

## 2. 共同根源 ✔

### 2.1 太陽黃經 λ☉：一條刻度、兩種切法

用引擎的 lunar-javascript 取 2026 年二十四節氣時刻，代回太陽黃經公式：

| 節氣 | λ☉ | | 節氣 | λ☉ | |
|---|---|---|---|---|---|
| 立春 | 315.00 | 節 → 寅月起 | 雨水 | 330.00 | 中氣 → 雙魚座起 |
| 驚蟄 | 345.01 | 節 → 卯月起 | 春分 | 0.00 | 中氣 → 白羊座起 |
| 清明 | 15.01 | 節 | 穀雨 | 30.01 | 中氣 → 金牛 |
| … | | | … | | |
| 小寒 | 285.00 | 節 → 丑月起 | 大寒 | 300.00 | 中氣 → 水瓶 |

二十四節氣就是太陽黃經每 15° 一個刻度。**十二「節」落在 315°+30k，是八字月柱的分界；十二「中氣」落在 30k，正好是西洋十二星座的分界。** 兩套系統切的是同一條線，只是錯開 15°。農曆「無中氣之月置閏」換成西洋的說法就是：一個朔望月裡沒有任何星座起點，就是閏月。

### 2.2 月亮黃經 λ☾

| 量 | 餵給 |
|---|---|
| λ☾ − λ☉（月距角） | 月相；朔（= 0°）定農曆初一 |
| 農曆月、日 | 紫微斗數：五行局 × 農曆日 → 紫微位置；農曆月 → 命宮 |
| λ☾ ÷ 30 | 月亮星座 |

紫微斗數十四主星的位置，根本上是由**月亮相對太陽的位置**決定的；西洋的月亮星座是同一顆月亮的絕對位置。

### 2.3 日周運動：時辰與上升點

| 量 | 餵給 |
|---|---|
| 真太陽時（經度差 + 均時差，引擎已有） | 八字時柱、紫微命宮與身宮 |
| 地方恆星時（經度 + 時刻） | 西洋上升點 ASC、天頂 MC |

紫微命宮「寅宮起正月順數到生月，再逆數到生時」◇ 是用農曆月當太陽位置、時辰當時角的查表版上升點；西洋 ASC 是同一個幾何量的連續版（東方地平線與黃道的交點）。

### 2.4 不是天象的部分

- 日柱、年柱是 mod 60 的純計數，不對應任何天體（但年干決定紫微四化、年支決定身主與太歲）。
- 太歲十二年一周來自歲星（木星）紀年 📜 —— 流年太歲是唯一和行星週期有歷史淵源的中式刻度。
- 外行星行運（土、天、海、冥）只有西洋有，中式沒有對應。

## 3. 分層架構

```
lib/sky/            天空層：時刻 + 經緯度 → λ☉、λ☾、行星黃經、恆星時、ASC/MC、節氣時刻、朔、月相、逆行
   ├─ astronomy-engine（MIT，日月行星全算，取代低精度公式與 Swiss Ephemeris 寫死表）
   ├─ lunar-javascript（農曆、節氣四柱，引擎已用）
   └─ true-solar-time.ts、dst-cn.ts（引擎已有；A 階段補台灣夏令時）
lib/bazi/           刻度層：四柱（直接用引擎 lunarInfo.fourPillars）、十神、大運、流年流月流日
lib/ziwei/          刻度層：iztro 引擎（已有）；流年／流月／流日改為即時算，不再查 2026–2033 表
lib/astro/          刻度層：星座、相位、逆行、本命點（ASC/MC 由出生資料算，不再寫死）
lib/advice/         文案層：十神文案（去個人化）、相位文案、四化文案、五行配色規則
app/                呈現層：天時地人 3D 空間 + 一條時間軸 + 三把尺
```

舊 app 各部分的去向：

| 舊 | 新 | 變化 |
|---|---|---|
| `TERM_BOUNDARIES` 固定日期 | `lib/sky` 以 λ☉ 跨 315°+30k 求節氣時刻 | 月柱誤差從 ±1 天降到分鐘級 |
| `dayGanzhi` 錨點 | 引擎 `fourPillars` | 已在引擎指紋內受保護 |
| `moonPhase` 平均週期 | λ☾ − λ☉ | 真實月相 |
| `MERCURY_RETRO` 表 | 每日算水星黃經，遞減即逆行 | 無到期日 |
| `YEAR_TRANSIT` 表 | 外行星黃經 × 本命點 → 相位 | 無到期日、任何人都能算 |
| `ZIWEI_YEAR` 表 | 引擎流年命宮即時 | 無到期日 |
| `NATAL` 寫死 | 出生資料 → ASC/MC | 男命上升從假設變成計算（仍標示出生時間精度） |
| `MALE_LIB`／`FEMALE_LIB` | `lib/advice/shishen.ts`，一套文案 + 依性別／角色的變體 | 去掉兩人的具體處境 |
| 看板、檢核清單 | 留在 `ours`（私人） | 不是命理工具的一部分 |

## 4. 呈現統整：一個時間、三把尺

- **唯一的時間控制**：現有 HUD 的時間軸（出生時刻 ⇄ 現在 ⇄ 任一日）。拖它，天空、八字、紫微、西洋同時更新，因為它們本來就是同一個 t 的函數。
- **三把尺並排**：每個尺度挑原生解析度最高的那把當主尺 ——

| 尺度 | 主尺 | 副尺 |
|---|---|---|
| 日 | 八字日柱十神（60 日循環） | 月亮星座（2.5 天換一次）、紫微流日 |
| 月 | 節氣月柱（λ☉ 每 30°） | 太陽星座（同一條線錯 15°）、紫微流月 |
| 年 | 紫微流年（太歲）、八字流年 | 木星、土星行運 |
| 十年 | 紫微大限、八字大運 | 外行星行運、土星回歸（29.5 年） |

- **天空就是星曆**：首屏那片星空和三把尺用的是同一個 `lib/sky`。使用者看到的太陽位置，同時是他的八字月、太陽星座、節氣；看到的月亮，同時是農曆日、月相、月亮星座。這是「共同根源」最直接的展示法。
- **多針**：地盤上大限針、流年針、流月針；天上北斗針、太陽、月亮。都是同一種轉動、不同轉速（concept.md §3）。
- **雙人**：兩個觀測者站在同一片天空下。引擎已有合盤；八字十神的「共同建議」規則化為兩人日柱十神的組合表。

## 5. 配色：五行色票

舊 app 的配飾表是「日主需要的元素 → 材質／避免的顏色」。規則化：

1. 五行色票（CSS tokens）：木＝青綠、火＝朱紅、土＝赭黃、金＝銀白、水＝玄青。
2. 個人喜忌：由日主與八字五行分布推喜用、忌神（舊 app 已有結論，新版由 `lib/bazi` 算，可覆寫）。
3. 每日配色 = f(日主, 當日日柱五行, 當月月柱五行)：給三色 —— 宜（喜用之色）、中（平衡）、避（忌神之色）—— 附一句理由（「今日庚金日，金生水，宜白、宜黑，避赭黃」）。
4. 站的主色預設不變（金／靛黑）；開關打開時，玻璃面板的邊光微調成當日「宜」色，幅度小，只當提示。

## 6. 隱私與 repo

- `bz.zhoujiayu.app`（本 repo）是公開工具：不放任何人的出生資料。個人檔案存瀏覽器 localStorage，要跨裝置再加 Cloudflare Access + KV。
- `ours.zhoujiayu.app` 保留私人用途（家族樹、看板、檢核清單）；`bazi-zodiac-calendar` 已封存，不動。
- 舊 app 的文案庫去個人化後搬進 `lib/advice/`；兩人的具體處境改成「情境標籤」（創業籌備、收入多元化），由使用者自己勾選。
- 本 repo 目前名字沿用上游 `ziwei-doushu`；產品定案後建議改名（GitHub 會自動轉址）。

| 項 | 方法 |
|---|---|
| 天空層 | 節氣時刻對照 lunar-javascript（誤差 < 0.02°，上面表格）；日月行星對照 astronomy-engine 自帶測試；新增 `sky-fingerprint.test.ts` |

## 8. 實作順序

1. `lib/sky`：接 astronomy-engine，先供節氣、月相、日月黃經；3D 原型的太陽改用它。
2. `lib/bazi`：四柱取引擎，十神，流年流月流日；每日配色。
3. `lib/astro`：星座、本命點、相位、逆行、外行星行運。
4. `lib/advice`：搬文案、去個人化。
5. 呈現：HUD 時間軸接三把尺；雙人模式。
